# ADR-0002: Waiting room เขียนเองด้วย Redis

**สถานะ:** ใช้งาน

## บริบท
ช่วงคนเข้าพร้อมกัน (เปิดลงทะเบียน, flash sale) ระบบหลังบ้าน โดยเฉพาะ database รับได้จำกัด
Rate limit อย่างเดียวจะปฏิเสธคนจริงที่มาพร้อมกัน ผู้ใช้เจอ error และคนกดเร็วได้เปรียบ

## ตัวเลือก
1. Cloudflare Waiting Room: ต้องใช้แพ็กเกจ Business ขึ้นไปและต้องมีโดเมนเอง
2. Virtual Waiting Room on AWS / Queue-it: ผูก vendor หรือคนละ cloud
3. เขียนเองด้วย Redis

## ตัดสินใจ
เขียนเองด้วย Redis

## กลไก
- `wr:tail` ตั๋วล่าสุด, `wr:released` ตั๋วสูงสุดที่ปล่อยแล้ว, `wr:last` เวลาที่เลื่อนตัวชี้ล่าสุด
- Lua script เลื่อน `released` ตามเวลา × อัตรา แบบ atomic ทุก instance เห็นคิวเดียวกัน
- เข้าคิวตอนคิวว่างจะรีเซ็ตนาฬิกา กันไม่ให้เวลาว่างสะสมเป็นเครดิตแล้วปล่อยคนทะลักเข้าทีเดียว
- ตั๋วคิวและบัตรผ่านเป็น JWT ผูกกับผู้ใช้ ปลอมหรือแชร์ไม่ได้
- ใช้คู่กับ rate limit: rate limit กันคนใช้งานผิดปกติ, waiting room จัดคิวคนปกติที่มาพร้อมกัน

## ผลที่ตามมา
- ไม่มีค่าใช้จ่ายเพิ่ม อธิบายและปรับได้
- Redis กลายเป็นจุดสำคัญ production ควรใช้ Memorystore หรือ Redis แบบมี replica
- ยังไม่กัน DDoS ระดับ network ต้องมี edge protection (Cloudflare / Cloud Armor) เพิ่ม
